## Selection and consent

Requests select exact namespace/source/predecessor/path tuples. Resolve every
path in that immutable historical flat root. Foreign owners, Job/Retention
sources, missing roots/paths, unknown coverage, size conflicts and exhausted
aggregate limits hold. Categories and deprecated-age evidence remain admitted
adapter responsibilities; names, Git dates and file modification times grant
neither meaning nor age. Explicit block selection works without an age filter.

Preview computes remaining membership across every admitted source, including
current/pending/predecessor Branch/Draft/Job/Retention roots and unselected aliases.
Only the exact selected historical paths are hypothetically removed. Unknown
closure holds; this projection grants no live absence/removal authority. Bind a
coherent checkpoint vector, exact selected bindings and original roots. Shared,
active, foreign-grant and otherwise held objects remain excluded from deletion
consent and their paths remain protected by the source subset replacement.
Later eligibility cannot expand that consent. Actual final deletion independently
rechecks live content-wide clearance and exact provider/birth/grants.

Canonical plan identity binds private enrollment, request, actual checkpoint
basis, exact selected/held/eligible subjects, owned subset plans and provider
plans, metadata witness store/capacity, clock policy and consent validity window.
Plan decoding/hashing is not authentication. The trusted owner/application admits
the exact plan; changed inputs need a new decision. Initial bounds are sixteen
historical roots, 1,024 selected paths, thirty-two unique objects/removal actions
and 48 KiB canonical plan, reserving space for job bindings in a 64 KiB intent.
Limit failures hold without partial consent. Larger inventories/plans belong in
bounded asset-side pages; this first bounded controller is not full bulk scale.

Multiple predecessor selections of one source must be planned as an exact
sequence using the existing source transition model. Earlier owned retirements
advance its revision; later plans must anticipate those exact changes instead
of becoming inevitably stale. Survivor enroll/adopt/withdraw retains the original
class and never exposes artificial active use. Unselected/held members survive.

## Durable control and action order

Use an explicitly enrolled existing non-removable LocalStore as metadata witness,
accounted immutable publication and CapacityLedger. No second journal/cleanup
engine. Fixed batch-scoped operation admission/attempt fencing coordinates only
the same batch; unrelated batches remain concurrent. Reserve intent, cancellation,
completion and control/recovery metadata before source settlement. Persist full
exact consent/plan and runtime job bindings before any owned claim changes.
Missing acknowledged intent/terminal evidence refuses repair under spent budget.

```text
validate exact independently admitted plan/basis and metadata peak
  -> durably acknowledge immutable batch intent
  -> apply exact owned historical subsets, preserving survivors
  -> recheck source consent and current final authority/window
  -> invoke existing guarded final provider per eligible object/store
  -> retain per-action historical/held/failed outcomes
  -> publish exact batch completion only when its actions are terminal
```

The initial exact-basis profile accepts only its own exact journal commands
after the approved checkpoint vector. Unknown intervening commands invalidate
pending destructive work even if a new claim was later withdrawn. This is
conservative for unrelated changes; predicate-specific incremental validation
remains future work. Check the validated history under the same live object
fences as final-provider clearance, so transient protection cannot slip between
consent validation and unlink. Old completed effects remain historical.
No SQL transaction spans metadata/provider IO and no global cache lock is used.

Cancellation durably stops future batch work under the batch control fence.
Before source settlement it preserves claims; after settlement it reports that
history retired with bytes present/unknown, without claiming source rollback.
Pending provider final operations use their existing cancellation semantics:
before grant release old grants survive, after release grants stay released,
and already absent authorized bytes recover deletion rather than rollback.
Cancellation cannot turn prior unapproved held members into deletion candidates.
Expired delete consent cannot authorize fresh unlink but does not prevent safe
owner-authorized cancellation or historical completion recovery.

Status is observational: distinguish intent, source settlement, provider release,
historical deletion/cancellation, incomplete scope and remaining debt. It creates
no repair or approval. Report versions/bindings/unique objects/unique bytes/copy
bytes separately; per-copy logical removal, original file allocation, metadata
charge and fresh capacity observations are distinct. Offline stores remain held,
and unknown external copies/provider versions are never reported erased.

## Required qualification

- Exact block across several historical roots; shared current/job/foreign demand
  and unselected aliases stay held/protected. A mixed root preserves held siblings.
- Same-source multiple predecessors execute in sequence with exact replay.
- Missing/corrupt metadata, unknown namespace scope, stale root/path and aggregate
  bounds refuse; no substring/path-prefix category or age interpretation.
- Full intent/job binding precedes source changes; metadata exhaustion and spent
  missing evidence hold. Wrong owner/context/window/plan cannot execute.
- Interruption before/after intent, subset adoption/retirement, provider release/
  unlink and terminal publication resumes exact effects without repeated loss.
- New source use, including prepare/abort between preview and apply, invalidates
  pending consent; final guards close the admission/unlink boundary.
- Cancellation before/after source settlement and provider release preserves
  truthful partial outcomes. No all-or-nothing batch promise.
- Historical replay versus fresh same-hash acquisition preserves the new birth.
- Canonical vectors independently pin new plan/intent/terminal framing before
  runtime acceptance; existing provider/source encodings remain unchanged.

L0: fmt, portable validator, reviewed hashes and diff. L1: focused/vector/negative,
locked default/all-feature workspace, strict Clippy and standalone Git. L2: actual
temporary metadata/source/provider/ledger effects, scoped race/child-exit and
measured byte assertions. Full age/category/native adapters, operator/UI surfaces,
large-file/real provider/current-clock/authority migration, metadata lifetime and
human intended-use acceptance remain required parts of the full product plan.

## Current library surface and limits

The in-progress final_retirement::bulk library supplies plan, strict Plan JSON,
exact authorize, and Execution::required_metadata_peak/status/apply/cancel.
Planning/status grant no deletion authority. No bulk CLI/Action/UI permission or
runtime is enabled. Request selections are sorted by namespace/source/predecessor
and exact paths; copy requests by store/object. Empty copy scope produces held
subjects, never inferred absence. The plan includes actual selected bindings,
per-object held reasons, filtered source subsets and exact eligible provider plans.
Canonical vectors include both held and eligible framing. The final provider's
additional Condition port cannot weaken mandatory live membership/provider checks.

Runtime enrollment, current roster/minima, metadata identity, witness job and
per-action jobs are independently supplied. A portable plan cannot lower private
trusted minima. Fresh execution rebuilds the exact preview before acknowledging
intent. Known journal history is bounded by the exact owned-command set and the
existing journal/record byte limits. History validation under final clearance
uses its refreshed, fenced snapshot: overlapping admission cannot advance it,
while unrelated partitions may advance without a global lock. Latest external
authority/minimum freshness and globally unseen restore detection remain adoption
gates; this controller does not invent an authority service or reset witnesses.

Metadata intent contains full plan plus metadata/job bindings. Fixed cancellation
and completion documents bind its plan/binding hashes. A separately admitted
batch control attempt fences only this operation. Terminal decisions are reread
after acquiring that fence, so a peer's cancellation cannot be missed. Each final
provider's metadata admission precedes owned source settlement. Cancellation
looks up original admissions and never creates a stale action that never started.
Unavailable or conflicting existing admissions remain explicit cancellation debt.

After a terminal decision, the alternate, never-published terminal reservation
uses existing authorized private-attempt cleanup with an exact empty partial-file
review. Unexpected bytes hold; acknowledged documents cannot be discarded.
Bindings remain charged, cleanup retries keep the same review, and historical
replay cannot reopen the cancelled publication. This permits closing the metadata
job without resetting a journal or borrowing reclaim. Source/provider jobs remain
caller-owned. Long-running journal continuation and stale-admission retirement
remain separate operational-lifetime work.

Reports name historical roots and bindings rather than inventing native asset
version semantics. Selected/eligible unique bytes, planned copy bytes, new logical
copy removal, historical deleted copy bytes, original file allocation and required
witness peak are separate. These observations grant no removal authority, volume
reclaim, secure erasure or proof about unknown external copies. Native asset counts
and age/category filters require their admitted adapters.
