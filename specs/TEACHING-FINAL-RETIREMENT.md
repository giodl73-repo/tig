## Fresh fixture enrollment

The current sample creates managed F/D and ordinary retained M. Those formats
cannot exercise final loss. The new mode must enroll fresh final-capable stores
using LocalStore::create_final and independently constructed complete fixture
roster, immutable owner/epoch/scope/clock policy and provider binding. Never
upgrade an old sample, strip a policy or manipulate provider payload files.
Use existing capacity/accounted publication/retention and native source adapters.
Reserve metadata witness state in a separate non-removable fixture provider.
F/D/M remain aliases for declared synthetic domains; hardware independence is
unproven. Existing roots continue to refuse before storage effects.

## One finite-storage story

1. Reproduce released/current versus deprecated F/D/M placement with the same
   shared/original/fixed public byte identities. Keep active draft/job protection.
2. Select exact obsolete occurrences in a named block and admitted categories.
   Independently retained inactivity proofs and a labelled simulated clock
   govern age; neither Git dates nor file modification times grant eligibility.
   Current, shared, job-protected, recent and unknown-age occurrences remain held.
3. Preview exact roots/paths, unique objects, per-store copies, survivors and
   exclusion reasons. A preview/digest/merge is not final-loss permission.
4. Independently construct fixture authorization for the exact admitted plan.
   Record this as explicit synthetic owner consent, never human approval. Recheck
   current protection, provider birth/grants and clock window under SDK fences.
5. Settle only the authorized historical subset; retain unselected/shared/job
   members. Invoke the existing final provider for the eligible original's
   managed copies. Final loss may leave zero managed copies only under this
   separate decision. Current fixed/shared bytes remain verified F+M.
6. Retry the exact operation after an injected supported boundary and show
   historical versus newly performed loss. Cancellation stops future actions,
   preserves prior loss and reports unknown cleanup honestly. A stale/expired
   decision refuses. No new journals, clocks or deletion implementation.
7. Separately admit same-hash reacquisition with a new provider birth; retrying
   the old deletion cannot remove those new bytes. Ordinary placement must not
   silently recreate deliberately retired bytes through the seed source.

Small bounded chapters may demonstrate these steps separately. Full acceptance
requires their continuous identity/provenance story, independently checked copy
sets and all named refusal/recovery scenarios, not a gallery of invented reports.

## Evidence protocol boundary

Current teaching reports embed placement::Plan/Report. A final bulk plan/report
must never be disguised as ordinary placement or a successful empty receipt.
Introduce an explicitly versioned/tagged bounded final-retirement observation
and reader validation before exposing it as an available lesson. Bind the exact
plan/authorization identity, current observed source basis, provider-role order,
object lengths/births, selected/held scope and actual effects. Authorization is
synthetic fixture evidence, not a browser capability. Unknown status is unknown,
not deleted; historical completion is not present-day custody.

Display before/preview/observed, claim settlement versus grant release/unlink,
eligible versus held unique/copy bytes, newly removed logical bytes and available
allocation evidence separately. Do not claim filesystem free-space gains from
logical removal. Expanding inventories/receipts stay asset-side; preserve64KiB
documents/responses,2MiB read budget and bounded chapter/report counts.
