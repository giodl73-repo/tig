## Storage closure and native meaning

Graph::storage_objects requires complete declared Production+Composition
coverage and explicit payload selection for every visited node. It includes
declared payloads of primary/container/output nodes plus exact interpretation
documents. Output bytes remain forbidden as production inputs; this new storage
view does not weaken production_requirements or claim complete native semantics.
Unsupported opaque closure holds. Profiles remain independently admitted, never
inferred from an instance's descriptive status or a filename.

The optional tig-git native adapter writes a candidate flat root through existing
Tree/NodeStore ports. A bounded header pins the exact native source archive,
canonical profile document and root index. Each root asset has independent paths
assets/RECORD_DIGEST/OBJECT_DIGEST for its complete declared storage closure.
Two assets sharing content retain two logical bindings to the same immutable
object, not two physical copies. Selecting one cannot remove the other's binding.
The reserved header binding keeps native interpretation available independently
of selected payload retirement. No expanded inventory is authored into Git.

Builder output is a candidate Source Selection. Provider finish/readback and
explicit owner adoption precede any protection claim. No existing arbitrary flat
root is silently treated as native or upgraded. The fresh root context is its
header digest. Owned subset transitions may change context; independent admission
of the original header identity plus exact current source minimum/root permits
reading those survivors without pretending the original full set still exists.

Inspection verifies the header, original snapshot/profiles/index and every actual
flat binding against the recomputed canonical full mapping. A retained subset may
omit original paths but cannot invent foreign paths, change sizes, substitute an
asset or rewrite category meaning. Remaining paths can be selected again; missing
members remain visibly retired bindings rather than silently reconstructed data.
Header/catalog presence is metadata, never a perpetual payload-retention claim.

## Exact selection and operator seam

An exact block names native record References (logical ID plus raw record object).
Categories map user labels to exact definition References in private admission.
No built-in cel/cue/golden vocabulary, path-prefix classifier or status inference.
When both block and category are supplied, intersect them. Empty filters refuse.
Unknown record/category, incomplete graph, foreign header/binding or aggregate
budget refuses rather than truncating consent. Reports distinguish original and
remaining bindings and emit one exact bulk::Selection for the admitted historical
namespace/source/predecessor. Bulk planning still checks all other roots, jobs,
aliases, custody/grants and current authority; selector output grants no deletion.

The explicit schema-feature CLI tig-retirement exposes describe, bind PROFILE,
and select PROFILE REQUEST. Bind opens an existing metadata store under its
trusted minimum, compiles the independently admitted source archive/root/profile
inputs, finishes and independently reads back the candidate before output. Select
opens only existing metadata/source handles, validates owner/class and exact
predecessor against independently admitted header identity, then emits bounded
JSON. It changes no source/provider/clock journal. Missing roots are not created.
Profiles, native metadata and reports remain private and outside project Git.

Limits bound source documents/bytes, total graph nodes/edges/returned bytes across
all root queries, metadata reads/writes/bytes, assets/bindings, elapsed work and
report size. Shared work is charged on every actual query/read; per-asset loops
cannot multiply a nominal per-query budget.
Archive acquisition shares the construction budget. Bind's independent persisted
readback is a second explicitly bounded phase under the same limits; both phases
must succeed before candidate acknowledgement. Existing source-journal admission
has its own bounded open/replay contract.
Initial inventories cap1024 roots and
65536 bindings; selected paths retain the existing bulk1024 ceiling and64 KiB
operator document/response bounds. Larger paged scopes remain product work.

## Age and remaining full-product gates

This slice supplies block/category mapping, not an age authority. No portable
timestamp, Git date, file mtime or descriptive metadata can mint retirement age.
The next age protocol must persist a conservative supersession-observation time
for an exact historical source occurrence through the existing publication/
ledger/clock ports. Unknown age holds. Reactivation creates or preserves other
current/recent historical obligations; selecting an old occurrence cannot erase
those protections. Freeze interval/window and replay semantics before enabling
age filters, then qualify real recorded evidence rather than supplied test dates.

Native age witnesses, full UI/Action integration, current authority/host trust/
unseen restore, large files/real providers, journal continuation, eventual
metadata retirement and human intended-use acceptance remain required parts of
the full plan. A native binding archive does not make any of them complete.
