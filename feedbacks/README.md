# Consumer integration lessons

Private feedback is preserved with its owner. This public summary retains
generic lessons, not project names, source pins, paths or acceptance claims.
Feedback does not itself change a contract or authorize storage operations.

- Component qualification and consumer runtime pins are separate. Inspect both
  before upgrading; a newer main is not automatic acceptance.
- Resolve exact captured metadata under admitted profiles. Retained contexts can
  survive unrelated Git commits without inventing another production run.
- Distinguish missing provider/payload/metadata knowledge from absent assets,
  stale outputs, parser failures and incomplete extraction.
- Restore should admit schemas, nested references and owned destinations through
  shared Rust primitives; avoid fixed project layouts.
- Large receipts/progress indexes belong asset-side. Preserve bounded reads,
  pagination and stale-result refusal.
- Reuse revision/delivery history, not a second project-specific receipt inventory.
  Delivery metadata does not verify a remote target now.
- Copies, retention, jobs, capacity and physical reclaim are different facts.
  A completed consumer workflow does not qualify generic eviction.
