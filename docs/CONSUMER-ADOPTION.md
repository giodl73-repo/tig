# Consumer adoption readiness

This is a generic acceptance boundary, not a claim that any particular project
has completed adoption. Component tests and a working catalog do not establish
whole-project production, retention or eviction readiness. Detailed project
checkpoints, private findings and operational evidence belong in project-owned
records or external enrollment notes. Original case-study notes remain in the deployment owner's verified archive.

Before a consumer transition, the owner must identify exact source snapshots,
definitions, schema/dialect contracts, logical IDs, payload profiles, producer
bindings and supported historical versions. Unknown/legacy formats remain
explicitly unsupported until an admitted adapter has fixtures and bounded reads.
No source path, provider or runtime binding changes merely by opening a view.

Acceptance must separately establish:

- Metadata identity, schema execution, exact selection and retained-history replay.
- Declared reference/variant resolution and the producer's actually consumed
  inputs, profiles, runtime and delivery contract; outputs cannot silently become
  production inputs. Evidence/composition/authority edges remain distinct.
- Missing/changed source behavior, source-valid/output-stale state, regeneration
  and delivery currency under actual consumer fixtures, not only synthetic tests.
- Exact guarded-byte readback, interruption/retry, capacity and scoped concurrent
  operations using the selected provider, including realistic large artifacts.
- Current roots, authorized drafts, active jobs and full retention obligations;
  incomplete coverage is unknown rather than zero demand or an orphan proof.
- Independently retained custody and fresh provider checks before any authorized
  replica removal, followed by measured physical reclaim and recovery evidence.
- Reversible consumer binding changes with preserved originals, rollback pins and
  explicit owner acceptance. Publication/creative/research approval is separate.

The generic component evidence register is [EVIDENCE.md](vtrace/EVIDENCE.md).
Its results close only their named scopes. Project labels, native mappings,
store locations and private qualification results are not Tig source constants.
Full producer/closure, job/custody coverage and removal acceptance remain open
unless the owning project records evidence for its complete selected scope.
