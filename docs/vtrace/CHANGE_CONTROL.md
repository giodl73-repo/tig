# Baseline change control

Trigger review when identity/canonicalization, persistent format, claim/authority,
provider capabilities, acknowledgement, reader/removal fencing, source selection,
retention, resource limits or public readiness claims change. Record affected
REQ/SPEC/IF/DES/PKG/WP, source/evidence and consumer compatibility before adoption.

Preserve stable TIG-R and doctrine IDs. REQ aliases do not rename obligations.
Wire/hash domains and .art compatibility need pinned migration vectors, not a
branding replacement. Keep changed baselines distinguishable from old accepted
snapshots. Unknown coverage and old authorities must not silently become current.

Every nontrivial package uses its explicit branch/scope, relevant validation
profile and named reviewer method. Revisit mitigation/invariant dispositions
when counterexamples are found; preserve failure memory and regression anchors.
Required unresolved safety/authority gaps keep affected live actions unavailable.

Version public requirements/format compatibility separately from mutable local
catalog generations. Keep durable operation/source IDs stable for replay. Do not
rewrite historical Git commits or remove retained bytes as process cleanup.
TRACKER portfolio snapshots remain separate from this repo's implementation.
